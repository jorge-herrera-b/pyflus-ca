# pyflus-ca

Python implementation of the cellular automata (CA) module of `FLUS_console`.

It uses an initial land-use map and a multiband GeoTIFF containing occurrence probabilities. It does not train the original neural network implemented in `nntrain.cpp`; the probability layers can be generated by FLUS, FT-Transformer, or any other land-use suitability model.

## Implementation details

- DAREA is disabled by default in the standard configuration.
- The stopping criterion follows the implementation defined in simulationprocess.cpp.
- CRS, geotransform, raster dimensions, and number of probability bands are checked before simulation.
- Land-use codes must be contiguous (`1..n_types`), and conversion matrices and neighborhood size are validated.
- Negative, NaN, and infinite probability values are rejected.
- The number of Numba threads is controlled through `simulation.thread`.
- Optional multi-period demand is supported through `simulation.demand_schedule`.
- The simulation period is recorded in the history CSV file.
- DAREA is available as an optional variant.

Pixel-level outputs are not expected to be identical to the original C++ implementation because NumPy/Numba and C++ `rand()` use different random-number generators. However, the main algorithmic structure is preserved: suitability, neighborhood effects, adaptive inertia, conversion matrix, roulette-wheel selection, and demand control.

`enclaves_for_landuse_type` is included in the log structure but is not used in the CA allocation procedure.

## Installation

```powershell
cd C:\path\to\pyflus-ca
python -m pip install -e .
```

To install the package and run the tests:

```powershell
python -m pip install -e ".[test]"
pytest -q
```

## Usage

Copy `flus_config_template.yml`, edit the input paths, land-use demand, conversion matrix, and neighborhood weights, and run:

```powershell
flus-ca inspect --config C:\path\to\flus_config.yml
flus-ca run --config C:\path\to\flus_config.yml
```

The package can also be executed without installing the command-line entry point:

```powershell
python -m flus_ca.cli run --config C:\path\to\flus_config.yml
```

## Probability bands

The GeoTIFF must contain exactly `n_types` bands. Band 1 corresponds to land-use class 1, band 2 to class 2, and so on. All raster inputs must share the same spatial grid.

## Multi-period demand

If `demand_schedule` is defined and is not empty, it overrides `future_pixels`:

```yaml
simulation:
  demand_schedule:
    - period: 2025
      future_pixels: [1000, 2000, 3000]
    - period: 2030
      future_pixels: [900, 2100, 3000]
```

Each period starts from the land-use map generated in the previous period, while adaptive inertia is reinitialized. The random seed is defined as `seed + period_index` to ensure reproducibility.

## DAREA

DAREA is disabled by default:

```yaml
hyperparameters:
  darea:
    enabled: false
```

Enable this option only when explicitly using the variant that favors a target land-use class when the restricted raster contains a designated value.
